# Wi-Fi 7 Automated Data Collection (Stage 1)

Welcome to the **Wi-Fi 7 Automated Data Collection** repository. This project provides the automation scripts and methodological framework required to empirically test and quantify the real-world performance degradation of Wi-Fi 7 (IEEE 802.11be). 

**Note: This is Stage 1 of the project.** 
The data processing, statistical analysis, and graphing tools for the logs generated by these scripts can be found in Stage 2 at:
👉 **[Wifi7AutomatedDataProcessing](https://github.com/quantifyingdegradationwifi7/Wifi7AutomatedDataProcessing)**

## Project Intent
Analytical propagation models and simulations often suggest idealized conditions for Wi-Fi 7. However, they struggle to fully capture multipath fading, material absorption, and environmental interference in complex indoor environments. Furthermore, early Wi-Fi 7 Multi-Link Operation (MLO) hardware currently relies heavily on Enhanced Multi-Link Single-Radio (EMLSR) fallback mechanisms rather than true simultaneous multi-radio transmission. 

This testbed uses a Design Science Research (DSR) methodology to collect **empirical, real-world data**. By leveraging Kali Linux, specialized drivers, and dual-adapter monitoring, these scripts allow researchers to simultaneously capture application-level capacity (iPerf3 throughput) and physical signal degradation (Wireshark RSSI/noise) across the 2.4 GHz, 5 GHz, 6 GHz bands, and MLO configurations.

## Hardware & Software Requirements
To replicate our exact testbed, the following hardware was used (though equivalent Wi-Fi 7 hardware can be substituted):
*   **Router:** ASUS RT-BE92U (BE9700) Tri-Band Wi-Fi 7
*   **Clients:** 2x Laptops (e.g., HP EliteBook 840 G10) running **Kali Linux**
*   **Receivers:** 2x TP-Link Archer TBE400UH (BE6500) Wi-Fi 7 USB Adapters per client
*   **Software:** iPerf3, Wireshark, custom compiled `wpa_supplicant-2.11`, and `rtw89` drivers.

## Repository Structure
*   `/scripts/setup_client.sh`: Fully automates the installation of dependencies, compilation of MLO-capable `wpa_supplicant`, `rtw89` DKMS driver installation, and configuration of `wlan1` (managed) and `wlan2` (monitor) interfaces.
*   `/scripts/diagnostics.sh`: A live-monitoring script that continuously syncs the monitor mode adapter (`wlan2`) to the active frequency and channel of the connected adapter (`wlan1`).
*   `/scripts/router_controller_poc.sh`: An SSH multiplexing script pushed to the ASUS router to dynamically toggle virtual interfaces (VIFs) between 2.4 GHz, 5 GHz, 6 GHz, and MLO modes without requiring manual GUI interaction.
*   `/scripts/run_iperf_tests.sh`: An automated prompting script that orchestrates the iPerf3 client runs, separating Line-of-Sight (LOS) baselines from obstructed environmental tests.
